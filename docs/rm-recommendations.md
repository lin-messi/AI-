# RM 推荐与 2027 空中系统

当前规则以 `data/rm-rules.json` 的任务清单为依据。补充的空中系统任务来自本地官方 2027 V1.0.0 手册：RMUC 比赛规则 3.2.1（印刷页27）和制作规范 2.4.4、S75-S83（印刷页31–35）。室内定位、规划、避障和机库交互是研究建议，不是将这些方向全部列为比赛强制考核。

推荐链路：

1. 机器人/视觉/学习分类抓取之外，单独查询 arXiv 无人机和自主降落主题，弥补各分类最新500篇的漏召回。
2. 以平台与自主飞行能力共同判定空中方向；卫星/航拍图像检测不会仅因 `aerial` 被标为空中自主飞行。
3. 依据当前规则任务关键词加权，写入 `rule_matches`；默认按规则相关度排序，可手动改为热度、星标或最新。
4. 在有真实候选时，每批60篇论文至少保留12篇空中方向；每日100篇合并池同样保留至少12篇。空中方向通常最多占35%，其他方向候选不足时才补空位。近90天窗口不变。
5. 通用库池仍为40个，至少保留10个合格空中方向候选（不够时不凑数）。白名单覆盖飞控、VIO、小型飞行器、规划、MPC和集群软件。开源整机仅作算法实现参考，尺寸、能源、通信等仍需按规则改造。
6. 规则任务及约束的指纹变化后，旧 `rm` 用途评估失效，下一次抓取重新生成；未配置AI或调用失败时不会继续展示旧规则建议。译文不因此清空。

`rules:build` 从全文不同位置选取相关章节，并在文档含全自动空中系统而提炼遗漏 `aerial` 时拒绝覆盖旧规则，避免再次只截取手册开头丢掉空中章节。

验证：`node --test tests/rm-recommendations.test.mjs`。

人工复筛已有归档、刷新最新推荐（无AI调用、不改历史归档）：

```sh
node scripts/refresh-rm-recommendations.mjs
```

可加 `--repo-metadata <json文件>` 导入从 GitHub `/repos/{owner}/{repo}` 取得的真实元数据。之后正常的定时抓取继续维护推荐池。
