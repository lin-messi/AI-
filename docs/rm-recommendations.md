# RM 推荐与 2027 空中系统

当前规则以 `data/rm-rules.json` 的任务清单为依据。补充的空中系统任务来自本地官方 2027 V1.0.0 手册：RMUC 比赛规则 3.2.1（印刷页27）和制作规范 2.4.4、S75-S83（印刷页31–35）。室内定位、规划、避障和机库交互是研究建议，不是将这些方向全部列为比赛强制考核。

推荐链路：

1. 机器人/视觉/学习分类抓取之外，单独查询 arXiv 无人机和自主降落主题，弥补各分类最新500篇的漏召回。
2. 以平台与自主飞行能力共同判定空中方向；卫星/航拍图像检测不会仅因 `aerial` 被标为空中自主飞行。
3. 依据当前规则任务关键词加权，写入 `rule_matches`；默认按规则相关度排序，可手动改为热度、星标或最新。
4. 在有真实候选时，每批60篇论文至少保留12篇空中方向；每日100篇合并池同样保留至少12篇。空中方向通常最多占35%，其他方向候选不足时才补空位。近90天窗口不变。
5. 通用库池仍为40个，至少保留10个合格空中方向候选（不够时不凑数）。白名单覆盖飞控、VIO、小型飞行器、规划、MPC和集群软件。开源整机仅作算法实现参考，尺寸、能源、通信等仍需按规则改造。
6. 规则任务及约束的指纹变化后，旧 `rm` 用途评估失效，下一次抓取重新生成；未配置AI或调用失败时不会继续展示旧规则建议。译文不因此清空。

`rules:build` 从全文不同位置选取相关章节，并在文档含全自动空中系统而提炼遗漏 `aerial` 时拒绝覆盖旧规则，避免再次只截取手册开头丢掉空中章节。

验证：`node --test tests/rm-recommendations.test.mjs`。

人工复筛已有归档、刷新最新推荐（无AI调用、不改历史归档）：

```sh
node scripts/refresh-rm-recommendations.mjs
```

可加 `--repo-metadata <json文件>` 导入从 GitHub `/repos/{owner}/{repo}` 取得的真实元数据。之后正常的定时抓取继续维护推荐池。

## 公开规则答疑

来源为用户指定的[RMU 2027 规则答疑公示面板](https://qingflow.com/appView/g79clgn1kk02/shareView/g79clh9dkk02?exWsId=1SdM5_PB-NwUtnyPn2b8)。`npm run rules:qa` 按网页的匿名共享视图流程初始化临时会话并读取全部分页，无需账号或长期Token，不保存Cookie。快照只保留问题编号、赛事、手册类型、问题与反馈、更新时间和附件存在标记，不保存学校、战队、用户身份字段。附件未识别时不将其用于自动建议。

2026-11-05读取335条，104条涉及空中系统。重点复核 #60/#11（机间通信定义）、#294/#26（离库与机库可见光链路）、#288/#323（光源与机载无线禁用等条件）。规则面板展示重点配对问答并链接完整来源。

答疑内容参与用途评估上下文与规则指纹；快照变化会使旧评估失效。提示词区分提问者假设与正式反馈，保留多问多答的完整对应关系；没有答复、身份填写类回复和依赖未识别附图的条目不作为自动建议依据。手册、答疑出现冲突时应提示复核，不能仅凭答疑编号认定效力。

在现有每日抓取流程的北京时间约13:37计划及手动执行时同步答疑，失败不清空旧快照。普通推荐抓取继续按既有周期执行。

## 中文译文

RM论文在最终筛选和当天合并完成后，补齐展示池内所有缺失的中文标题和摘要，不再限制为前40个标题；精选论文另有精读。新译文会填回旧条目的空字段，已有校对内容和精读保留。

手工复筛归档后，运行 `npm run repair:rm-translations` 补齐当前快照。该命令先复用历史译文，再调用已配置的AI服务，只改当前RM快照和通用库；不抓取、不重新排序、不重写历史日期。每批完成即保存，失败时保留已成功的译文，并以非零退出码报告尚未完成的数量。可用 `-- --no-ai` 仅复用已有译文并检查缺失。

## 可见光通信精准推荐

单独的 `optical` 类别覆盖帧/滚动快门/事件相机，以及光电二极管和LED接收路线，不再要求文献必须包含UAV。检索范围包含通信与信号处理分类 `cs.IT/cs.NI/eess.SP`，并在筛选及当日合并中保护合格候选。新增来源兼顾 arXiv 真实日期排序、GitHub 按星标与近期更新双路检索。

可见光主体、数据链路和收发器件共同用于判断；不把VideoLAN/libVLC、仅红外/光纤/远程激光链路、没有可复现证据的纯资源分配或数值信道分析当作目标实现。低星并非自动淘汰：经过人工核验、具备代码与硬件说明的细分原型可收录，但只标为实现参考，不凭空声称高影响或宽松许可。

`data/rm-optical-catalog.json` 保存逐条核验的接收器、用途、限制与原始来源；`npm run fetch:rm-optical` 刷新 arXiv、Crossref 和 GitHub 元数据。正常采集复用最多7天的证据缓存，API失败保留旧证据及其原核验日期。近期论文仍由每次采集的定向搜索补充；经典库不因一年没有提交被误删。快照只复筛最新日期，不改写历史归档。

近期标签按真实发表或代码更新时间的365天窗口判断，不使用首次收录日期。长期参考启发式为：至少两年的明确实现论文具有至少30次可核验Crossref索引引用，或至少两年的已核验实现仓库具有至少100个GitHub Stars。阈值只用于分类和有限加分，不等同于保证质量；低星作者代码、仿真和数据资源仍可作为有明确限制的参考。Crossref计数不是全网总引用数，界面提供来源链接和核验日期。

2026-11-05的当前快照有10篇光通信论文（5篇近一年、2篇长期参考、3篇其他研究参考）、4个相关项目。两类接收端可分别筛选。每张卡展示推荐原因、硬件/许可/部署限制、真实日期和证据；没有原始摘要的DOI条目只展示推荐说明，不凭标题生成摘要或精读。

答疑上下文优先关联#184、#194、#168、#288、#294和#26。额外通信LED的PWM/OOK许可不能套用到七颗航行外观灯，照度要求保留安装对象与测量条件，不因项目使用“可见光”就自动判为符合比赛规范。
